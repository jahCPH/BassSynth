## 0. Scope and non-goals

PsyRoot is a psytrance bass instrument plugin (AU + VST3, macOS 13+, universal) with three mono engines,
a host-synced step sequencer/arp per engine, and a shared bus (duck, sub ownership, mono low, master drive).

In scope for v0.1: audio graph, event/timing model, voice model, DSP blocks per engine, bus, parameter list
with defaults, state, UI data contract, test hooks.

Not in scope: visual layout (Astra), build/release (Cursor, reusing Vizuator's process). Licensing is decided
(L1: 7-day trial + Moonbase); its implementation is Cursor's and stays off the audio thread.

## 1. Signal flow

```
            ┌──────────── MIDI in (host) ────────────┐
            ▼                                         │
      MIDI ROUTER ──(duck note, only if DUCK SRC=MIDI)──► DUCK TRIGGER
            │
            ├── held-note set ──► ARP ──► per-engine STEP LANE (SEQ mode)
            └── direct notes ─────────────► per-engine voice (MIDI mode)
                                                │
   host PPQ / transport ──► SEQUENCER CLOCK ────┘

 ENGINE 1 ROLLING ─┐   each engine: voice(2 slots) → LOW CUT (AUTO/ON/OFF) → DUCK GAIN → LEVEL
 ENGINE 2 SLIDING ─┼─► SUM ─► MONO LOW (crossover, width only) ─► MASTER DRIVE (OS) ─► OUTPUT ─► host
 ENGINE 3 FX ──────┘
 SUB (sine, generated by the SUB OWNER engine's voice, after its filter, before its low cut bypass)
 DUCK ENVELOPE (INTERNAL quarter notes | MIDI note | AUDIO sidechain) ─► gain on targeted engines
```

All engines are mono internally. Stereo appears only where an engine or the master adds width (FX
movement, optional width stage). MONO LOW therefore mostly guards FX and master width.

## 2. Threading and timing

### 2.1 Threads
- **Audio thread:** all DSP, all event handling, sequencer. No allocation, no locks, no logging.
- **Message/UI thread:** parameter edits via APVTS, pattern edits via a lock-free command queue
  (SPSC, UI → audio), display data via snapshots (audio → UI, see §9).
- Pattern data lives in two copies (double buffer). UI writes the inactive copy and publishes it with
  an atomic swap; the audio thread swaps at the next block start. No torn patterns.

### 2.2 Sample-accurate events
- Each `processBlock` builds one **sorted event list** for the block: incoming MIDI (with sample offsets),
  sequencer steps due in this block, INTERNAL duck triggers, transport changes.
- The block is processed in **sub-blocks split at event positions**, so every note-on, step and duck
  trigger lands on its exact sample.
- **Zero added scheduling delay:** no event is ever moved later to solve a DSP problem. Fixed latency from
  oversampling filters is reported to the host via `setLatencySamples` (see §7) and is separate.

### 2.3 Sequencer clock (host-synced)
- Source: `AudioPlayHead` PPQ position, tempo, time signature, `isPlaying`.
- Step position is **derived from PPQ every block**, never accumulated. Loops, jumps and tempo ramps
  resync automatically.
- Step boundary for step `n` at rate `r` (in quarter notes, 1/16 = 0.25):
  `ppq_n = n * r + swingOffset(n)`; converted to a sample offset inside the block from tempo + sample rate.
- **Swing:** global value with per-lane override (`FOLLOW GLOBAL` or own value). Swing delays every
  odd-indexed step by `swing * r / 2` (0–75%, default 0%).
- **Transport stop:** the sequencer stops; sounding SEQ-lane notes get a note-off at the stop sample (release
  runs). Direct-MIDI voices, the routing table and the held-note set are **kept**: their routes stay valid
  until the host's note-offs arrive (§3.3). Stop does not clear routing.
- **Transport not available / standalone:** sequencer idle. (proposal) Free-run at a fixed BPM is a later
  feature.
- Pattern length 1–16 steps per lane (default 16); rate 1/8, 1/16, 1/32, 1/8T, 1/16T (default 1/16).

## 3. Event layer

### 3.1 MIDI router (first stage, per incoming event)
1. CC123 / CC120 (all notes / all sound off) → clear routing table, release all voices, clear held set.
2. Note-on: decide the route **once** and store it in the routing table keyed by (channel, note#):
   - `DUCK` if DUCK SOURCE = MIDI and note# = DUCK NOTE (default **36**) and channel matches
     (default ANY). Consumed unless DUCK PASS-THROUGH = ON (default OFF, then also routed normally).
   - otherwise `NOTES`.
3. Note-off: follow the route stored at its note-on, **regardless of current settings**. Then clear the entry.
4. Source or note changes while notes are held: affect new note-ons only.
5. Pitch bend → all engines in MIDI mode (range ±2 st default). Mod wheel → mappable (default: cutoff of
   engines in MIDI mode). Aftertouch ignored in v0.1.

### 3.2 Per-engine SOURCE: SEQ / MIDI  (proposal: per engine; INIT = SEQ on all)
- **SEQ:** `NOTES` events update the shared **held-note set**. The engine's step lane plays; pitch comes
  from the arp (§3.4).
- **MIDI:** the engine's lane is bypassed (pattern kept). `NOTES` events drive the engine's voice directly:
  mono, last-note priority, note stack for returning to a still-held note.
- Switching SEQ ↔ MIDI while sounding: release the current voice at the switch sample.

### 3.3 Routing table
- Fixed-size array 16 ch × 128 notes of a small enum. No allocation.
- Cleared **only** together with releasing every voice and the held-note set: on CC123/CC120,
  `prepareToPlay`, `reset`, and state load. Transport stop does **not** clear it (§2.3).
- Guarantee: **no stuck notes** from any combination of source changes, mode switches or transport events:
  either a note keeps a valid route to its note-off, or its voice is released at the same moment the route is
  cleared.

### 3.4 Arp (SEQ mode pitch source)
- Input: held-note set (ordered by arrival, max 16 notes).
- Order: UP / DOWN / UP-DOWN / AS PLAYED / RANDOM (default UP). **Decided** (Q1). No Converge/Diverge/Chord
  modes: with a mono bass they add nothing.
- **LATCH** (default OFF): held notes stay in the held-note set after release until a new note-on (starts a new
  set) or LATCH off / CC123 / transport stop clears it. One tap on the root keeps the roll going.
- The arp advances **once per step that triggers a new note** (not on tied steps, not on rests).
- **One arp index per lane**, one shared ARP ORDER. **Decided** (Q3); lanes have independent rate/length, so a
  shared index would drift.
- Later, not v1: per-step probability and a per-step expression lane (useful for FX).
- Nothing held (and LATCH off or empty) → lanes trigger nothing (silent). **Decided** (Q1).
- Per-step **pitch offset** (−24…+24 st) is added to the arp note. **Decided** (Q2): unlike index-based arps
  (e.g. Serum 2), offsets are what make a single held root move (octave jumps, fifths, 303-style lines).
- Per-lane **TRANSPOSE** (−24…+24 st, default 0) is added on top: note = arp note + step offset + lane transpose.

### 3.5 Step model (per lane, per step)
| Field | Range | Default | Notes |
|---|---|---|---|
| on | bool | pattern | |
| gate | 5–100% of step, or TIE | 50% | TIE = legato into the next step |
| velocity | 1–127 | 100 | |
| accent | bool | off | |
| pitch offset | −24…+24 st | 0 | |
| glide mode | FOLLOW / OVERRIDE | FOLLOW | FOLLOW = use the lane GLIDE knob live |
| glide value (destination) | 0–100% of a step | — | used only in OVERRIDE; glide applies only when the previous step TIEs into this one |

- A step whose previous step is TIE: **no retrigger**, same voice, glide to the new pitch.
- A step that follows a non-tied step: **retrigger** (new voice, §4.2).

## 4. Voice model

### 4.1 Per engine
- Musically **mono**. Technically **2 voice slots**: `active` and `tail`.
- One voice = oscillator(s) + sub (if owner) + filter + amp env + filter env + drive state.

### 4.2 Retrigger (SEQ step or direct note-on that is not legato)
1. A fresh voice starts **on the scheduled sample**. Amp env from 0, min attack ~0.5 ms.
2. Reset honours the toggles:
   - PHASE RESET ON: osc phase = start phase (0 for saw, defined per waveform). OFF: inherits phase from
     the outgoing voice (continuous oscillator).
   - FILTER RESET ON: filter integrator state, drive state and DC blocker state = 0. OFF: inherited from the
     outgoing voice.
3. The outgoing voice moves to `tail` and fades out over ~2 ms (raised-cosine), in parallel.
4. Third note while a tail is still fading: **(Cursor to validate)** bounded strategy, e.g. a tail
   accumulator or a defined steal of the oldest tail with a short ramp. Behaviour requirement: no click
   above the test threshold (§11), onset still on the scheduled sample, CPU bounded, dense MIDI included.

UI/manual wording: **"same starting state on every hit"**, never "bit-identical". Velocity, accent,
modulation and the arp still differ between hits.

### 4.3 Legato and glide
- Legato (TIE in SEQ, overlapping notes in MIDI): same voice, envelopes not retriggered, glide to the new pitch.
- Glide curve: **constant time, linear in semitones**.
- Glide time units: **SEQ** = % of one step (stored), ms computed at the current tempo for display.
  **Direct MIDI** = its own stored value in **ms** (`*_glide_ms`), independent of tempo and of the SEQ value.
  Switching SOURCE never retimes either value.
- **SEQ clamp:** if glide time > destination gate, the glide is shortened to the gate length so the pitch
  arrives before release. The audio thread publishes, per step: `requested` (% + ms), `effective` (% + ms)
  and `clamped` (bool), so the UI can label the effective value, not just flag it.
- **Direct MIDI:** no clamp (future note-off unknown). On note-off the release starts and the pitch keeps
  gliding to its target during the release.

### 4.4 Envelopes
- Amp env: ADSR (A 0.5–200 ms, D 5 ms–4 s, S 0–100%, R 2 ms–2 s), exponential segments.
- **Time convention:** A = time from 0 to peak (linear-ish). D and R = time for the exponential segment to fall
  to **−60 dB** of its span (D: peak → sustain, R: current level → 0). A note-off during D starts R from the
  current level.
- So a hit's length = min(gate, A + D) + R. Example INIT Roll at 145 BPM: gate 50% of a 103.4 ms step =
  51.7 ms note-off, then R 12 ms → audible tail ends ≈ 64 ms, inside one 16th.
- Filter env: AD (+ optional sustain), separate DECAY from amp. LINK toggle (Rolling) couples filter
  decay to amp decay as a macro (proposal).
- Accent: +amp (default +4 dB) and +filter env amount (default +30%), targets selectable (Sliding inspector).

## 5. Engines

### 5.1 Common blocks
- **Oscillators:** band-limited saw/square with polyBLEP (polyBLAMP for hard sync later). Phase-reset safe.
- **Sub:** sine one octave below (option: same octave), level 0–100%, generated only in the SUB OWNER engine,
  added **after** the voice filter so filter sweeps don't thin it.
- **Voice filter:** TPT/ZDF 4-pole ladder (24 dB LP, default) with resonance, plus 12 dB SVF mode in the
  inspector. Cutoff and env are modulated per sample (smoothed), keytracking 0–100%.
- **Drive:** asymmetric soft clip (tanh-family) + DC blocker, **oversampled** (§7).
- **Smoothing:** all continuous params smoothed (5–20 ms), cutoff in log domain.

### 5.2 ROLLING (engine 1)
Main panel: CUTOFF · ENV AMT · FILTER DECAY · AMP DECAY. Visible toggles: PHASE RESET · FILTER RESET.
Inspector: reso, drive, osc shape (saw / square / mix), tune/octave, vel→filter, keytrack, filter mode, LINK.

### 5.3 SLIDING (engine 2)
Main panel: CUTOFF · RESO · GLIDE (lane default) · ACCENT.
Inspector: env amt, filter decay, amp decay, drive, osc shape, accent targets, glide units display.

### 5.4 FX (engine 3)
Main panel: FM AMOUNT · FORMANT · MOVEMENT · RATE.
- **FM:** 2-op, modulator → carrier phase modulation, ratio 0.5–8 (inspector), FM amount env-able.
  Runs oversampled (aliasing).
- **Formant:** 3 parallel band-pass resonators, vowel morph A-E-I-O-U on one axis (FORMANT).
- **Movement:** tempo-synced LFO (RATE: 1/32…4 bars, shapes sine/tri/S&H) to FM amount + formant, depth
  MOVEMENT. Retrigger on step or free (inspector). Optional stereo spread (this is what MONO LOW guards).
- **FX LOW CUT:** own HPF, default ON at 150 Hz, 24 dB/oct.

## 6. Bus

### 6.1 Per-engine chain: voice → LOW CUT → DUCK → LEVEL
- **LOW CUT mode AUTO / ON / OFF** (Rolling + Sliding, default AUTO). Freq 40–300 Hz (default 100), slope
  12/24 dB/oct (default 24).
  - AUTO = ON if the engine is not the sub owner, OFF if it is.
  - SUB OWNER = OFF → no owner → AUTO = OFF on both bass engines (full range).
  - The audio thread publishes the **effective** state for the UI.
  - Wording: reduces low-end overlap; it does not remove it.
- **Overlap flag:** published when both bass engines are active and both are full range (for Astra's quiet
  indicator).

### 6.2 SUB OWNER: ROLL / SLIDE / OFF  (default ROLL)
- Changing owner while playing: sub crossfades over ~10 ms; low-cut AUTO states follow.

### 6.3 Duck
- Gain envelope per trigger: attack fixed ~1 ms, optional hold (0–50 ms, default 0), RELEASE 10–500 ms
  (default 120 ms), curve LIN/EXP (default EXP). DEPTH 0–100% with dB readout (100% = −∞ dB at the trough).
- Targets: per-engine toggles ROLL / SLIDE / FX (default ROLL + SLIDE ON, FX OFF).
- Sources:
  - **INTERNAL:** trigger on every host quarter note (PPQ integer). Sample-accurate. Assumes a 4/4 kick;
    label says so.
  - **MIDI:** trigger note (default 36, channel ANY) via the router (§3.1). Sample-accurate.
  - **AUDIO:** host sidechain bus (VST3 aux input, AU sidechain). Envelope follower + threshold +
    re-trigger hold-off; base on Vizuator `TransientDetector` (sub-100 Hz band). Reacts after the transient
    (a few ms late); not presented as tight as INTERNAL/MIDI. (proposal) optional lookahead later.
- Missing input, **no silent fallback:**
  - AUDIO, sidechain bus not enabled / not routed by the host (bus disabled or 0 channels) → `NO BUS`, duck inactive.
  - AUDIO, bus connected but below threshold for > 2 s → `SILENT` (informational; duck simply not triggering).
  - Hosts that don't report bus connection: treat as connected; only `SILENT` can show. Documented per host.
  - MIDI without triggers → `WAITING`. INTERNAL with transport stopped → `STOPPED`.

### 6.4 MONO LOW (width only)
- **Side-channel high-pass**, not a band-split crossover: M = (L+R)/2, S = (L−R)/2, S' = HPF(S),
  out L = M + S', out R = M − S'. The HPF is a 4th-order (LR4-style, 24 dB/oct) high-pass at the MONO LOW freq.
  Freq 50–250 Hz (default 120). Never linked to LOW CUT.
- Why not an LR4 split + recombine: an LR4 low/high sum is an allpass, so it would phase-shift the whole
  signal, including mono content. With the side-only filter a **mono signal (S = 0) passes bit-identical by
  construction**, and only the stereo difference below the freq is removed (its phase is shifted near the
  corner, which is acceptable for width control).
- UI wording stays "stereo width below X Hz", never "bass removal".

### 6.5 MASTER DRIVE + OUTPUT
- Master drive 0–100% (default 0 in INIT), oversampled, with output compensation (proposal: auto-gain off by
  default, user-switchable).
- OUTPUT −24…+6 dB. A final safety soft limit at 0 dBFS is **(proposal)**, default OFF (we don't hide levels).

## 7. Oversampling policy
- Oversampled blocks: per-engine drive, FM, master drive. Factor 2x default, 4x option (global
  "QUALITY: NORMAL / HIGH"). It changes the reported latency, so it needs a visible home in the UI (footer or a
  settings panel; Astra's call), not only the inspector.
- Filter type: polyphase IIR (low latency) by default (proposal); linear-phase only if listening tests
  require it. **Report latency** to the host; changing QUALITY updates the latency.
- Voice filters run at base rate with a TPT topology (stable at high cutoff); revisit if self-oscillation
  aliases audibly at 44.1 kHz.
- **(Cursor to validate)** CPU budget target: < 3% of one M1 core at 48 kHz, 2x, all three engines active with
  tails; 4x < 6%.

### 8.1 INIT preset ("INIT / ROLLING")
- Rolling ON, Sliding and FX OFF, lanes empty except Roll.
- Roll lane: steps 2-3-4, 6-7-8, 10-11-12, 14-15-16 ON (12 hits), gate 50%, velocity 100, no accents.
- Phase reset ON, filter reset ON.
- Roll amp env: A 0.5 ms · D 70 ms · S 0% · R 12 ms. Roll filter env: A 0.5 ms · D 60 ms · S 0%.
  With gate 50% at 145 BPM the note-off comes at 51.7 ms (during D) and the tail ends ≈ 64 ms (§4.4), inside
  the 103.4 ms step.
- Sub owner ROLL, duck INTERNAL 45% / 120 ms on Roll + Slide, mono low 120 Hz, swing 0%.

## 9. UI data contract (audio → UI, lock-free snapshots, ~30–60 Hz)
- Current step per lane, playing flag, per-step glide `requested` / `effective` / `clamped`.
- MIDI IN activity (last note-on time), held-note set (for the arp display).
- Duck: source state (`ACTIVE` / `NO BUS` / `SILENT` / `WAITING` / `STOPPED`), current duck gain, trigger activity.
- Effective LOW CUT state per engine, overlap flag, current sub owner.
- Output peak per channel; optional spectrum feed via an `AudioRingBuffer` copy (Vizuator) on the UI thread.
- Displays draw from **parameters** (env shapes, glide curves, waveform computed from params), not from
  live audio-thread scopes.

## 10. State and versioning
- `getStateInformation`: APVTS tree + pattern data + `stateVersion` (start at 1).
- `setStateInformation`: reject blobs > 1 MB, clamp every value to its range, fill missing fields with
  defaults (Vizuator `PluginStateSanitize` pattern). Unknown future fields are ignored, not fatal.
- Loading state while playing: release all voices, clear routing table, swap pattern at the block start.

## 11. Test hooks (unit tests from day 1)
1. Sequencer timing: onsets land on the exact sample across block sizes 1…2048, sample rates 44.1–192 kHz,
   tempo changes, loop jumps, swing.
2. Zero added scheduling delay: a retrigger onset equals the scheduled sample with PHASE/FILTER RESET on/off.
3. Click test: retrigger at high reso + drive; peak of the second difference below a threshold
   (threshold set by Cursor from listening).
4. No stuck notes: randomized fuzz of note-on/off, CC123, duck source changes, SEQ/MIDI switches, transport
   stop → zero sounding voices after all note-offs.
5. Glide: SEQ clamp correctness; direct-MIDI glide continues through release.
6. Duck: INTERNAL triggers on PPQ integers; MIDI note consumed only when the source is MIDI; AUDIO
   `NO BUS` vs `SILENT` states.
7. MONO LOW: a mono signal (L = R) passes bit-identical; a side-only signal below the freq is attenuated by
   the HPF response; M/S round trip is exact for any input with MONO LOW at its minimum (HPF bypassed).
8. Aliasing: a swept saw through drive at 2x/4x, energy above the folding threshold below the target.
9. CPU budget (§7) as a benchmark, not a pass/fail gate in CI.
10. State: round-trip, oversized blob rejected, out-of-range values clamped.
11. Carried over from Vizuator: dev paths off in distribution (REL-001), duplicate-track test, host
    track-info test (UAT-005).
